# Cairn — WhatsApp Assistant Integration & Setup Guide

This document provides a comprehensive, battle-tested, end-to-end guide on how Cairn's WhatsApp Assistant works, how to configure and run it locally for free using Meta's Cloud API and ngrok, and how to troubleshoot every real-world edge case and gotcha discovered during development.

---

## 1. Architectural Overview

Cairn does **not** connect to a physical phone via Bluetooth or browser automation. Instead, it integrates directly with the **Meta WhatsApp Cloud API (Graph API v21.0)**.

Meta hosts the virtual WhatsApp phone number in their global cloud infrastructure. When a user messages that number, Meta forwards the message to Cairn's webhook. When Cairn wants to reply or send proactive reminders, it calls Meta's REST API.

```
┌────────────────────────────────────────────────────────┐
│             User's Personal Mobile Device              │
│                 (WhatsApp Messenger)                   │
└───────────────────────────┬────────────────────────────┘
                            │
               1. User sends: "bill Electricity 1200 15-Oct"
                            │
                            ▼
┌────────────────────────────────────────────────────────┐
│               Meta WhatsApp Cloud API                  │
│       (Hosts the virtual project phone number)         │
│          Graph API v21.0 / WABA Engine                 │
└─────────────┬────────────────────────────▲─────────────┘
              │                            │
   2. HTTP POST Webhook                    │ 5. HTTP POST Graph API
      (X-Hub-Signature-256)                │    (Send confirmation / reminder)
              │                            │
              ▼                            │
┌──────────────────────────────────────────┴─────────────┐
│                 Cairn API (NestJS)                     │
│               Port 3000 (/api prefix)                  │
│                                                        │
│  - Verifies HMAC-SHA256 signature (WHATSAPP_APP_SECRET)│
│  - Normalizes sender phone to E.164 (+91...)           │
│  - Looks up User & active Household in database        │
│  - Parses command via parseWhatsAppCommand()           │
│  - Auto-creates domain records (Bill, Task, Document)  │
│  - Emits EventLog (BILL_DETECTED / TASK_EXTRACTED)     │
│  - Dispatches automated confirmation reply             │
└───────────────────────────┬────────────────────────────┘
                            │
                            ▼
┌────────────────────────────────────────────────────────┐
│                 Cairn Web (Next.js)                    │
│               Port 4200 (/dashboard)                   │
│                                                        │
│  - Overview: Enriched Activity Timeline (Badges)       │
│  - Tasks Board: Shows generated tasks with zero-shadow │
│    confirmation dialogs on status changes / deletion   │
│  - Settings: Household phone registration & Guide      │
└────────────────────────────────────────────────────────┘
```

## 2. Credentials & Environment Reference

To avoid the common trap of conflating tokens, secrets, and IDs, review this credential inventory:

| Environment Variable       | Where to Find It in Meta Console                                  | Purpose                                                                                                                         |
| :------------------------- | :---------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------ |
| `WHATSAPP_PHONE_NUMBER_ID` | **WhatsApp &rarr; API Setup &rarr; Step 1**                       | Numerical ID of the sending phone number (e.g. `1322208520978898`).                                                             |
| `WHATSAPP_ACCESS_TOKEN`    | **WhatsApp &rarr; API Setup &rarr; Step 1**                       | Bearer token used by Cairn to call Meta Graph API (or permanent System User token).                                             |
| `WHATSAPP_APP_SECRET`      | **App settings &rarr; Basic &rarr; App Secret** (Click _Show_)    | Meta's secret used to generate HMAC-SHA256 signatures on inbound POST payloads (`X-Hub-Signature-256`).                         |
| `WHATSAPP_VERIFY_TOKEN`    | **Generated by you** (any high-entropy string)                    | Shared secret entered into Meta Webhook configuration and Cairn `.env` for initial handshake verification (`hub.verify_token`). |
| `WABA_ID` _(Setup only)_   | **WhatsApp &rarr; API Setup &rarr; WhatsApp Business Account ID** | Numerical ID of your WABA (e.g. `987882574313863`) used for the `subscribed_apps` Graph API call.                               |

### Environment Configuration (`.env.local` / `.env`)

```env
# Meta WhatsApp Cloud API credentials
WHATSAPP_PHONE_NUMBER_ID="1322208520978898"
WHATSAPP_ACCESS_TOKEN="EAAG..."
WHATSAPP_VERIFY_TOKEN="cairn_webhook_verify_token_2026"
WHATSAPP_APP_SECRET="a3f7c19d4e28..."
```

## 3. Step-by-Step Setup Guide

### Step 1: Create Meta Developer App & Add WhatsApp

1. Navigate to [developers.facebook.com](https://developers.facebook.com) and log in.
2. Click **My Apps** &rarr; **Create App**.
3. Select **Other** &rarr; click **Next**.
4. Choose **Business** as the app type &rarr; click **Next**.
5. Enter an app name (e.g. `Cairn Assistant`) and your email &rarr; click **Create app**.
6. Under **Add products to your app**, locate **WhatsApp** and click **Set up**.
7. Select or create your Meta Business Portfolio.

> [!TIP]
> **Can't find the WhatsApp menu?** If WhatsApp does not appear in your left sidebar, click **Dashboard** in the top left, find the **WhatsApp** card under **Add products to your app**, and click **Set up**. Once set up, the left sidebar will show **WhatsApp** &rarr; **API Setup** and **Configuration**.

### Step 2: Authorize Your Personal Phone Number (Development Mode)

In development mode, Meta only allows sending/receiving messages to explicitly verified test numbers:

1. In the left sidebar, click **WhatsApp** &rarr; **API Setup**.
2. Under **To**, click the dropdown and select **Manage phone number list**.
3. Add your personal mobile number including the country code (e.g. `+91 98765 43210` or `+1 415 555 2671`).
4. Meta sends a 6-digit verification code to your WhatsApp. Enter the code to verify.

### Step 3: Configure Permanent Tunnel (`pnpm ngrok`)

Meta's servers must be able to reach your local NestJS backend (`http://localhost:3000`).

#### 1. Why Ngrok with a Static Domain?

- **Cloudflare Tunnel (`cloudflared`) Pitfall**: In many local network environments or Indian ISPs, running `npx cloudflared tunnel --url http://localhost:3000` frequently fails with:
  `failed to request quick Tunnel: Post "https://api.trycloudflare.com/tunnel": context deadline exceeded (Client.Timeout exceeded while awaiting headers)`.
- **Default Ngrok Pitfall**: Running plain `ngrok http 3000` generates a random domain that changes every time you restart your terminal, forcing you to re-verify the webhook URL in Meta Console every session.
- **Solution**: Claim a free static domain in your [ngrok Dashboard](https://dashboard.ngrok.com/cloud-edge/domains) (e.g. `secret-motivator-jukebox.ngrok-free.dev`).

#### 2. Authenticate Ngrok (Fix `ERR_NGROK_4018`)

If you encounter:

```text
ERROR: authentication failed: This ngrok session is not authenticated.
ERR_NGROK_4018
```

Run this command with your authtoken from [dashboard.ngrok.com/get-started/your-authtoken](https://dashboard.ngrok.com/get-started/your-authtoken):

```bash
ngrok config add-authtoken <YOUR_AUTHTOKEN>
```

#### 3. Run the Dedicated Script

Cairn provides a pre-configured script in `package.json`:

```json
"scripts": {
  "ngrok": "ngrok http --url=secret-motivator-jukebox.ngrok-free.dev 3000"
}
```

Start the tunnel in a persistent terminal:

```bash
pnpm ngrok
```

### Step 4: Configure Webhook in Meta Console

1. In Meta Developer Console, go to **WhatsApp** &rarr; **Configuration**.
2. In the **Webhook** section, click **Edit**:
   - **Callback URL**: `https://secret-motivator-jukebox.ngrok-free.dev/api/webhooks/whatsapp`
     _(Notice the `/api` prefix! NestJS sets `app.setGlobalPrefix('api')`)._
   - **Verify Token**: Enter your `WHATSAPP_VERIFY_TOKEN` (e.g. `cairn_webhook_verify_token_2026`).
3. Click **Verify and Save**. Meta will issue a `GET` request with `hub.mode=subscribe` and `hub.challenge`. Cairn validates the token and echoes the challenge (`200 OK`).
4. Under **Webhook fields**, click **Manage**, and click **Subscribe** next to **`messages`**.

### Step 5: The Crucial WABA Subscription (`subscribed_apps`)

> [!CAUTION]
> **The "2 Gray Checkmarks / Zero Ngrok Requests" Trap**:
> If you skip this step, messages sent to your test number will show **2 gray checkmarks** on WhatsApp (delivered to Meta's servers), but **ngrok will receive ZERO requests**.
> By default, Meta routes incoming test webhooks to their sample app, NOT your app, until you explicitly subscribe your App ID to your WABA.

Execute this one-time cURL command in your terminal (substituting your actual `WABA_ID` and `WHATSAPP_ACCESS_TOKEN`):

```bash
curl -i -X POST "https://graph.facebook.com/v21.0/987882574313863/subscribed_apps" \
  -H "Authorization: Bearer EAAG..."
```

**Expected Response**:

```json
{ "success": true }
```

You can verify the active subscription at any time:

```bash
curl -i -X GET "https://graph.facebook.com/v21.0/987882574313863/subscribed_apps" \
  -H "Authorization: Bearer EAAG..."
```

### Step 6: Open the 24-Hour Customer Care Window

Meta WhatsApp Business API strictly enforces a **24-hour service window**:

- A business bot **cannot** send freeform replies or proactive text to a user unless either:
  1. The user texted the business within the last 24 hours.
  2. Or the business sent an approved **Template Message**, which the user answered.

To establish the initial connection:

1. In Meta Developer Console &rarr; **WhatsApp** &rarr; **API Setup** &rarr; **Step 2: Send and receive messages**.
2. Select your verified test phone number in the **To** dropdown.
3. Click **Send message** (this sends Meta's pre-approved `hello_world` template).
4. On your personal WhatsApp, open the message from the test number and send any reply (e.g. `hi`).
5. The 24-hour bidirectional messaging window is now open.

## 4. Household Phone Registration & E.164 Standard

When an inbound message arrives, Meta sends the sender's phone number as a clean digit string (e.g. `919876543210`). Cairn normalizes this to E.164 (`+919876543210`) and looks up the user in the database:

```typescript
const phone = `+${message.from}`;
const user = await this.prisma.user.findUnique({
  where: { phone },
  include: { memberships: true },
});
```

If the sender's number is not registered or has no active household membership, the message is ignored:
`Inbound WhatsApp message from unregistered number +919876543210`.

### Registering Your Phone in Cairn UI

1. Navigate to `http://localhost:4200/dashboard/settings/household`.
2. Locate the **WhatsApp Integration & Phone Number** section.
3. Select your country code from the dropdown (built with `react-phone-number-input` and native country flags) and enter your number.
4. Click **Save Phone Number**.
5. Use the in-page **WhatsApp Connection Guide** to copy sample commands with 1 click.

## 5. Supported Commands & Automatic Database Action

Cairn does not just log incoming messages into an audit table; it creates real, actionable domain entities in the PostgreSQL database:

### 1. Bill Command (`bill`)

- **Syntax**: `bill <Vendor> <Amount> [DueDate]`
- **Examples**:
  - `bill Electricity 1200 15-Oct`
  - `bill Internet 899 tomorrow`
  - `bill Rent 25000 2026-10-01`
- **Actions Executed**:
  1. Creates `Bill` record (`vendor: "Electricity"`, `amount: 1200`, `currency: "INR"`, `dueDate: 2026-10-15`).
  2. Creates associated `Task` (`description: "Pay Electricity bill (₹1200)"`, `dueOn: 2026-10-15`, `status: "OPEN"`).
  3. Records `BILL_DETECTED` event in `EventLog`.
  4. Dispatches WhatsApp confirmation: _"Got it -- added to your household tasks & digest."_

### 2. Task Command (`task`)

- **Syntax**: `task <Description> [DueDate]`
- **Examples**:
  - `task Buy groceries tomorrow`
  - `task Fix water purifier 20-Oct`
  - `task Call electrician`
- **Actions Executed**:
  1. Creates `Task` record on your household board (`description: "Fix water purifier"`, `status: "OPEN"`).
  2. Records `TASK_EXTRACTED` event in `EventLog`.
  3. Dispatches WhatsApp confirmation.

### 3. Document Tracking Command (`doc`)

- **Syntax**: `doc <LabelOrType> [ExpiresOn]`
- **Examples**:
  - `doc passport 2030-05-20`
  - `doc vehicle insurance 2027-01-15`
- **Actions Executed**:
  1. Resolves `type` against Prisma `DocumentType` enum (`IDENTITY`, `FINANCIAL`, `LEGAL`, `PROPERTY`, `VEHICLE`, `MEDICAL`, `OTHER`) using `toDocumentType()`.
  2. Creates `Document` record (`type: IDENTITY`, `label: "passport"`, `expiresOn: 2030-05-20`).
  3. Creates renewal `Task` (`description: "Renew passport before expiration"`, `dueOn: 2030-05-20`, `status: "OPEN"`).
  4. Records `DOCUMENT_EXPIRING` event in `EventLog`.
  5. Dispatches WhatsApp confirmation.

## 6. Where Can I See the Created Records?

When you send a command like `bill Electricity 1200 15-Oct`, Cairn writes to multiple layers. You can inspect the results across four interfaces:

1. **Dashboard Overview (`/dashboard/overview`)**:
   - The **Activity Timeline** lists recent events with status badges (e.g. `BILL_DETECTED` with Vendor: `Electricity`, Amount: `₹1200`, Status: `Pending`).
2. **Tasks Board (`/dashboard/tasks`)**:
   - The task (e.g. `Pay Electricity bill (₹1200)`) appears under **Open Tasks** with due date and priority badge.
3. **Documents Page (`/dashboard/documents`)**:
   - Tracked documents appear with expiration countdowns and status.
4. **Prisma Studio (Direct Database View)**:
   - Run in your terminal:
     ```bash
     pnpm prisma studio
     ```
   - Open `http://localhost:5555` to view raw tables: `Task`, `Bill`, `Document`, `EventLog`, `User`, `Household`.

## 7. Dashboard UX & Zero-Shadow Status Protection

- **Tasks Board (`/dashboard/tasks`)**:
  - **Accidental Click Protection**: In previous versions, clicking task status chips (`OPEN` &rarr; `IN_PROGRESS` &rarr; `DONE`) or the delete button would mutate state immediately with no confirmation.
  - **Confirmation Dialog**: Changing task status or deleting a task now triggers an accessible zero-shadow modal (`AlertDialog`). Users can confirm or cancel before the mutation runs.
  - Adheres strictly to Cairn's **zero-shadow design system** (`shadow-none`, border-focused visual hierarchy).

## 8. Clean Restart & Cache Troubleshooting

If you suspect cached processes or stale state:

1. **Stop all active terminals**: Press `Ctrl+C` in running `pnpm dev` and `pnpm ngrok` terminals.
2. **Clear build artifacts (if needed)**:
   ```bash
   rm -rf .nx/cache apps/web/.next dist
   ```
3. **Start the API & Web server**:
   ```bash
   pnpm dev
   ```
4. **Start the tunnel in a separate terminal**:
   ```bash
   pnpm ngrok
   ```
5. **Verify health**:
   - API: `curl http://localhost:3000/api/health`
   - Web: Open `http://localhost:4200`
   - Ngrok Web Inspector: Open `http://127.0.0.1:4040` to see real-time HTTP requests.

## 9. Battle-Tested Troubleshooting Matrix

| Symptom / Error                                                                                                | Root Cause                                                                                                | Exact Solution                                                                                                                                 |
| :------------------------------------------------------------------------------------------------------------- | :-------------------------------------------------------------------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------- |
| **Meta Webhook Setup: `404 Not Found`** (`GET /webhooks/whatsapp`)                                             | Callback URL is missing the NestJS `/api` global prefix.                                                  | Set Callback URL to `https://<DOMAIN>/api/webhooks/whatsapp`.                                                                                  |
| **Meta Webhook Setup: `403 Forbidden`** (`GET /api/webhooks/whatsapp`)                                         | `WHATSAPP_VERIFY_TOKEN` in `.env` doesn't match the Verify Token entered in Meta Console.                 | Ensure both strings are identical.                                                                                                             |
| **Inbound Webhook: `403 Invalid webhook signature`**                                                           | `WHATSAPP_APP_SECRET` is missing, misconfigured, or confused with `WHATSAPP_VERIFY_TOKEN`.                | In Meta Console &rarr; **App Settings** &rarr; **Basic**, copy **App Secret** (not verify token) and paste into `WHATSAPP_APP_SECRET`.         |
| **User sends message, 2 gray checkmarks on WhatsApp, but ngrok receives 0 requests**                           | The WABA is not subscribed to your developer app. Meta routes test messages to internal sample app.       | Run Graph API POST command: `curl -i -X POST "https://graph.facebook.com/v21.0/{WABA_ID}/subscribed_apps" -H "Authorization: Bearer {TOKEN}"`. |
| **Ngrok fails with `ERR_NGROK_4018: This ngrok session is not authenticated`**                                 | Missing ngrok authtoken on local machine.                                                                 | Run `ngrok config add-authtoken <TOKEN>` with token from [dashboard.ngrok.com](https://dashboard.ngrok.com/get-started/your-authtoken).        |
| **Cloudflare tunnel fails: `context deadline exceeded (Client.Timeout)`**                                      | Cloudflare quick tunnels are blocked or timing out on local ISP.                                          | Use ngrok with reserved static domain instead: `pnpm ngrok`.                                                                                   |
| **Meta Console: Cannot find WhatsApp sub-menu or Webhooks**                                                    | WhatsApp product has not been added or left sidebar is unexpanded.                                        | Go to App Dashboard &rarr; **Add products to your app** &rarr; click **Set up** on WhatsApp.                                                   |
| **NestJS logs: `Inbound WhatsApp message from unregistered number +91...`**                                    | The sender's phone number is `null` or formatted incorrectly in the `User` table.                         | Go to **Settings &rarr; Household**, enter your phone with country code using the country picker, and click **Save**.                          |
| **Graph API outbound returns `400 Bad Request` (`Recipient phone number not in allowed list`)**                | In development mode, the recipient number has not been authorized.                                        | Go to **API Setup &rarr; Manage phone number list**, add the number, and verify with the 6-digit code.                                         |
| **Graph API outbound returns `400 Bad Request` (`Template needed outside 24h window`)**                        | The 24-hour service window expired or was never initialized.                                              | Go to **API Setup &rarr; Send and receive messages**, send the `hello_world` template, and reply to it from WhatsApp.                          |
| **Graph API returns `401 Unauthorized` (`OAuthException`, code `190`, subcode `463` / `Session has expired`)** | Temporary development access tokens expire after 24 hours.                                                | Follow Section 10.3 to create a permanent Meta System User Admin token with expiration set to **Never**.                                       |
| **TypeScript compile error: `Type 'string' is not assignable to type 'DocumentType'`**                         | Prisma generates strict enums for `DocumentType`. Raw strings from chat parser cannot be passed directly. | Use the helper function `toDocumentType(rawType)` in `whatsapp.service.ts` to map strings safely.                                              |
| **Webhook triggers, EventLog is created, but no records on Tasks or Bills page**                               | Webhook was previously only writing to `EventLog` and not instantiating domain models.                    | Ensure `whatsapp.service.ts` calls `prisma.bill.create()`, `prisma.task.create()`, and `prisma.document.create()`.                             |
| **Tasks immediately complete or delete on accidental click**                                                   | Missing user confirmation flow.                                                                           | Use the zero-shadow `AlertDialog` confirmation modal in `task-row.tsx`.                                                                        |
| **Ngrok URL changes every time terminal restarts**                                                             | Using dynamic ngrok endpoints without a reserved domain.                                                  | Claim a free static domain in ngrok dashboard and run via `pnpm ngrok` (`ngrok http --url=<DOMAIN> 3000`).                                     |

## 10. Transitioning to Production & Permanent Access Tokens

When ready to roll out Cairn for family members or production users without test whitelists or 24-hour session restrictions:

### 1. Provision a Dedicated Phone Number

You do not need a physical SIM card or extra phone. You can use:

- A virtual VoIP number (e.g. Twilio, Skype, or local VoIP providers for ~$1/month).
- A spare eSIM or SIM.
- An office or landline number (Meta verifies via automated voice call).

> [!NOTE]
> The phone number must **not** be registered to an active personal WhatsApp app. If it is, delete the WhatsApp account in the mobile app settings first.

### 2. Register the Production Number in Meta Console

1. In Meta Developer Console &rarr; **WhatsApp** &rarr; **API Setup**, scroll down to **Step 5: Add a phone number**.
2. Follow the wizard:
   - Enter your Business Display Name (e.g. `Cairn Household Assistant`).
   - Select Category (e.g. `Finance` or `Personal / Productivity`).
   - Enter the phone number and select **SMS** or **Voice Call** verification.
3. Enter the 6-digit verification code.
4. Meta assigns a permanent production `WHATSAPP_PHONE_NUMBER_ID`. Update this in your production environment variables.

### 3. Generate a Permanent System User Token (Never Expires)

By default, the token generated under **WhatsApp &rarr; API Setup &rarr; Step 1** is a temporary test token that expires after **24 hours**, resulting in:

```json
{
  "error": {
    "message": "Authentication Error",
    "code": 190,
    "type": "OAuthException",
    "error_subcode": 463
  }
}
```

To eliminate 24-hour expirations for both local testing and production, generate a permanent System User Token:

#### Step A: Navigate to System Users in Meta Business Suite

- **Direct Link**: Go to [business.facebook.com/settings/system-users](https://business.facebook.com/settings/system-users).
- **Via Meta Developer Console**: In the left sidebar, click **App roles** &rarr; **Roles**, then click the **"Edit roles in Meta Business Suite"** button on the right, and navigate to **Users &rarr; System users** in the left menu.

#### Step B: Create an Admin System User

1. In the **System users** panel, click **Add** (or **Create system user**).
2. Enter a **System user name**: e.g. `cairn-bot` or `cairn-system-user`.
3. **CRITICAL**: Change **System user role** from _Employee_ to **Admin**.
4. Click **Create system user**.

#### Step C: Assign WhatsApp Account Asset Permissions

1. Select your new system user and click **Add Assets**.
2. On the left panel, click **WhatsApp Accounts** (or **Apps**).
3. Select your WhatsApp Account (e.g. `Cairn Assistant`).
4. On the right panel, toggle ON **Full control** (e.g. **Manage WhatsApp account** / **Manage app**).
5. Click **Save Changes**.

#### Step D: Generate the Token with Permanent Expiry

1. Click **Generate new token**.
2. Select your App: `Cairn Assistant`.
3. **Token expiration**: Select **Never**.
4. Under permissions, select:
   - `whatsapp_business_messaging` (required to send WhatsApp messages)
   - `whatsapp_business_management` (required to manage business assets)
5. Click **Generate Token**.
6. Copy the generated token string immediately (Meta will not display it again).

#### Step E: Update Cairn Environment Variables

Save the permanent token into your [`.env.local`](file:///Users/selvaganapthi/SelvaGanapathi/prj/cairn/.env.local) or production secrets:

```bash
WHATSAPP_ACCESS_TOKEN="EAAG..."
```

Restart your dev server (`pnpm dev`). Cairn can now dispatch outbound WhatsApp alerts indefinitely without token expirations.
